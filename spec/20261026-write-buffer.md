# 降低錄製時的磁碟寫入

## 摘要

- 盡量降低頻繁的磁碟寫入，不用特別精準。
- 每個直播間的記憶體緩衝 4–64 MB 可選，預設 16 MB；全部加起來 64–256 MB，預設 64 MB。
- 程式結束前如果有機會寫入，就嘗試寫一次。

錄製的資料先留在記憶體，攢到上限才一次寫進磁碟。

原本每個檔案有 1 MB 的寫入緩衝。桌面版開著邊錄邊播時，每寫完一個片段（約每個關鍵幀間隔，1–4 秒）還會強制寫出一次。邊錄邊播的片段直接從記憶體送給播放器，不讀檔案，不需要這個強制寫出。

## 緩衝上限

| 設定 | 範圍 | 預設 |
| --- | --- | --- |
| 每路錄製的緩衝 | 4–64 MB，每 4 MB 一格 | 16 MB |
| 所有錄製加起來的緩衝 | 64–256 MB，每 32 MB 一格 | 64 MB |

- 一路錄製的緩衝滿了，就整批寫進檔案。
- 所有錄製的緩衝加起來超過總上限時，正在寫的那一路先把自己的緩衝寫出去；寫完還是超過（別的直播間佔滿了），這一筆直接寫進檔案。不追求精準。
- 每路的上限在開始錄製時決定，改設定後下一次錄製才生效。總上限改了立刻生效。
- 以碼率 8 Mb/s 估算，16 MB 約是 16 秒的錄影，也就是大約每 16 秒寫一次磁碟。
- 命令列加上 `--buffer`（每路，MB）和 `--buffer-total`（總計，MB）兩個選項，預設值同上。

## 什麼時候一定寫出

- 切分段、斷線重連、換解析度：關閉目前的檔案之前。
- 停止錄製、直播結束：封裝最後一個分段之前。
- 錄製出錯或程式內部錯誤（panic）：緩衝物件被釋放時。
- 程式結束：
  - 桌面版關閉視窗、Cmd+Q、從 Dock 結束、系統登出或關機：先停止所有錄製、寫出緩衝並自動合併，完成後才結束。原本只有關閉視窗會這樣做。
  - 收到 SIGTERM 或 SIGINT（macOS 和 Linux）：桌面版和命令列都同上。命令列原本只處理 Ctrl+C。
- 被強制結束（`kill -9`、當機、斷電）時沒有機會寫出，最多遺失每路一個緩衝的資料。

## 驗證

- 單元測試：
  - 未滿上限時不寫進檔案；
  - 滿了整批寫出；
  - 超過總上限時先寫出；
  - 釋放時寫出剩下的。
- 錄一段模擬直播，用 `fs_usage` 看寫入次數比改動前少，錄出的檔案照常可以解碼。
- 錄製中按 Cmd+Q，錄製會封裝、合併完才結束，最後一個分段完整。

## 不在範圍內

- 用 `fsync` 強制落到實體磁碟。
- 依剩餘記憶體自動調整上限。
